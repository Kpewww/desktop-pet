# 用 Codex 做一只自己的桌宠（全流程与可复制 Prompt）

这份教程与 [Claude Code 版](TUTORIAL_CLAUDE_CODE.md) 对应：使用同一个预制包，让 Codex 根据照片和设定修改形象、服装、台词与动作，最后打包成 Windows 桌宠。

**推荐顺序：准备 → 只读理解 → 计划 → 确认形象 → 完成制作 → 检查 → Windows 真机验收 → 打包。**
每一阶段复制对应提示词即可。想少复制几次，可以直接用文末的总提示词。

## 0. 先准备好

| 项目 | 说明 |
|---|---|
| Windows 10/11 | 这个项目使用 Windows .NET Framework 编译器和 WinForms；最终运行和验收需要 Windows |
| Codex | 使用能访问本地项目的客户端或 IDE 扩展；CLI 也可以。安装、登录与账户可用性以官方说明为准 |
| 项目文件 | 用 Git 克隆，或从 GitHub 下载 ZIP 并解压 |
| 参考资料 | 可选：本人、朋友或宠物的授权照片；也可以完全用文字描述 |
| 角色设定 | 名字、发型、默认衣服、性格、口头禅、喜欢的食物 |

官方入口：[Windows 使用说明](https://developers.openai.com/codex/windows)、[IDE 扩展](https://developers.openai.com/codex/ide)、[CLI](https://developers.openai.com/codex/cli)。

建议在 **Windows 本地项目 + PowerShell** 环境完成。仅连接 GitHub 的云端会话可以修改文件，但不等于能看到你的 Windows 桌面或完成桌宠真机测试。已有 WSL 工作流可以继续使用，但这个仓库的构建命令要在具备所需编译器的 Windows 环境执行。

下载项目（已安装 Git 时，在 PowerShell 运行）：

```powershell
git clone https://github.com/Kpewww/desktop-pet.git
cd desktop-pet
```

如果目录已存在，直接打开原目录，不要重复克隆或覆盖。下载 ZIP 的用户直接打开解压后的项目根目录。

在 Codex 中选择该目录。模型使用账户当前可用、适合代码和图片理解的模型；复杂形象和动作可以提高推理强度，简单台词修改使用默认设置即可，不必固定某个型号或购买最高档套餐。

### 照片怎么放

可以通过客户端支持的图片附件入口提供，也可以放在本地 `reference_pics/` 下，让 Codex 用可用的图片读取工具查看。看不到图片时，应让它明确说明，不能仅凭文件名猜外形。

`reference_pics/` 用来避免把原照片提交到 Git，但仍应检查忽略规则。**Git 忽略不等于照片只在本机处理**：发送给 Codex 的内容会按所使用服务的条款和数据设置处理。分享仓库或压缩包前检查是否混入照片、私人姓名或其他个人资料。

## 1. 只读了解项目

先发这一段，不急着制作：

```text
请先只读理解这个桌宠仓库，暂时不要修改文件或运行构建。

1. 阅读适用的 AGENTS.md（如果存在）、README.md、docs/MAKE_YOUR_PET.md、
   art/README.md、docs/ANIMATION_GUIDE.md 和 build.ps1。
2. 检查实际有哪些宠物，确认示例宠物路径、构建方式、图集与预览输出位置。
   文档和实际文件不一致时，指出差异，以当前实现为依据。
3. 检查当前系统、Shell、Windows .NET Framework 编译器与 Git 状态。
   若没有 Git 元数据，说明这是解压目录，不要把它当成错误。
4. 区分：当前环境能修改哪些文件、能否构建、能否在我的桌面运行。
5. 用简短中文说明一只宠物由什么组成，以及制作前还缺什么信息。

保护已有修改，不读取无关的私人资料，不安装依赖或改变系统设置。
```

这一步的结果应该是“项目结构和可执行条件”，而不只是复述 README。

## 2. 计划与角色设定

客户端提供 Plan 模式时先切换到 Plan；CLI 可以使用 `/plan`。如果界面没有这个入口，直接发送下面“只做计划”的提示词。不要照搬 Claude Code 的快捷键。

把方括号替换成自己的信息；不想定制的项目写“沿用示例”。

```text
现在只做计划，不要修改文件。

我要基于当前项目制作一只专属桌宠：
- key：[例如 mochi；使用小写字母开头的简短英文标识]
- 显示名：[麻薯]
- 是谁：[我本人／朋友／我的猫拟人化／原创角色]
- 参考图片：[附件或 reference_pics/ 中的具体文件]
- 识别特征：[发型、发色、眼镜、挑染、耳朵、尾巴等]
- 身材比例：[例如保留示例的像素比例，头不要继续放大]
- 默认服装：[奶黄色毛衣、深色裤子、白鞋]
- 额外服装：[先做一套睡衣]
- 发型变化：[沿用示例机制，或具体要求]
- 性格：[有点傲娇，开心时话多]
- 口头禅：[哼～／知道啦／陪你一会儿]
- 喜欢的食物：[名称和希望的反应]
- 功能：[保留现有功能；列出不需要的功能]
- 双宠：[这次只做一只／需要与某只已有角色互为伙伴]
- 不能改的地方：[例如保留侧边挑染，不加猫耳，不改变肤色]

请先查看图片，提炼最有辨识度的 3～5 个可见特征；
看不清的细节不要编造。告诉我哪些效果能通过现有配置实现，
哪些需要新增部件、动作或引擎逻辑。

计划分为：
A. 创建独立角色与第一版形象；
B. 我确认形象后，完成全部动作、造型和台词；
C. 构建、检查、修复；
D. Windows 真机验收和打包。

列出每阶段的修改范围、预览文件和验收标准。
只询问影响外形或实现范围的关键问题；其余提出合理默认值。
```

确认计划后，切回可执行模式或选择客户端提供的实施入口，再发送下一段。计划模式里的同意消息不应被理解为绕过客户端权限。

## 3. 创建角色，先做形象

```text
按刚才确认的计划开始阶段 A。

先检查目标 key 是否已存在；如果存在，检查现有进度后继续，
不要删除、覆盖或再次运行 new。
如果不存在，使用 build.ps1 的 new 命令从 example 新建角色。

沿用当前文本像素图管线，修改 art/<key>/ 中的调色板与部件，
以及 assets/<key>/character.txt。不要用一张生成的 PNG 替代
项目所需的部件、clips 或 atlas，也不要重写引擎。

先完成头部、发型、脸、默认服装与整体比例，保留现有动作结构，
检查这些部件在代表性动作中是否可用。
确认 id 唯一且只含英文字母和数字，快捷键不冲突。

环境允许时运行：
.\build.ps1 art -Char <key>

打开并检查生成的预览，再向我展示默认形象及代表性动作。
重点检查辨识特征、头身比例、轮廓、颜色对比和图层遮挡。
如果不能生成或查看图片，明确说明，不要声称已经看过。

本阶段做到形象预览后暂停，等我确认外观。
```

> 上面的 `<key>` 是占位符，执行时必须换成真正的角色 key，例如 `mochi`。

反馈尽量具体，例如“眼睛间距缩小一格”“耳朵与头发区分不够”“侧面挑染位置反了”。不要一次只说“不像”，让 Codex 知道要保留和修改什么。

修改提示词：

```text
保留当前已经确认的部分，只修改以下外观问题：
1. [具体问题]
2. [具体问题]

请修改源部件后重新生成图集，检查共享这些部件的相关动作。
展示修改前后的对应预览，并说明实际改了什么。
没有提到的五官、衣服和比例不要自行重新设计。
```

## 4. 形象定稿后，完成整只宠物

```text
形象确认了。按已批准的计划完成阶段 B 和 C，直接完成必要修改、
构建与问题修复，不要每改一个文件就停下来问。

要求：
1. 完成已约定的动作、服装、发型、食物和台词；不增加未约定的大功能。
2. 修改文本源文件，让构建工具生成 atlas 和 icon，不手工修改生成文件。
3. 保留锚点、动态眼睛、举牌和镜像动作的机制。
   plain 图集会隐藏 ears/tail，其他部件不能依赖这些图层的锚点。
4. 检查站立、左右走跑、坐下、睡觉、被拎、摔倒、吃东西、
   摸头、生气、换装和举牌等实际存在的动作。
   确保头发、衣服、手脚和道具不穿帮，进入退出不突兀。
5. 服装换色与服装轮廓变更分开处理；轮廓变化需要相应部件，
   不要把仅改颜色说成新款式。
6. 保留必要台词场景，避免删掉测试要求的项目。
7. 如果涉及共享引擎修改，说明原因，并检查示例角色是否受影响。

在 Windows 构建环境执行：
.\build.ps1 art -Char <key>
.\build.ps1 -Char <key>
.\build.ps1 test

检查退出码和输出。测试失败先定位原因，修复本次引入的问题；
不要删除测试或降低断言来制造通过结果。
区分原有故障和本次故障。

打开 _sheet.png、相关 clip_*.png、_outfits.png，
用当前工具支持的方式检查 gif_*.gif 或逐帧预览。
_sheet.png 只展示动作首帧，不能代替完整动画检查。

交付：修改摘要、实际检查结果、预览路径、需要我真机确认的事项。
遇到缺失环境或权限时说明具体阻塞，完成仍可执行的部分，不伪造成功。
```

可选：支持 `/goal` 的客户端，可以在计划批准后把“完成上述已批准制作与检查任务，形象确认和真机验收处等待用户”设为目标。它用于跟踪任务，不保证无限运行，也不代替权限与验收。无需该命令也能使用上述流程。

## 5. Windows 真机验收

在自己的 Windows PowerShell 中执行（以下以 `mochi` 为例）：

```powershell
.\build.ps1 run -Char mochi
```

如果 Agent 启动后你看不到窗口，可能是运行环境或桌面隔离导致的；先在你自己的交互桌面运行，不要直接认定渲染坏了或关闭安全设置。

| 检查项 | 亲自确认 |
|---|---|
| 基础显示 | 角色大小、位置、透明背景是否正常 |
| 交互 | 拖拽、摸头、戳、喂食、右键菜单是否正常 |
| 动作 | 左右行走、坐下、睡觉是否穿帮或跳帧 |
| 外观切换 | 换装、发型和耳尾开关是否正常 |
| 陪伴功能 | 番茄钟、提醒、防干扰、陪看是否符合设置 |
| 窗口行为 | 是否意外抢焦点，透明位置是否能点穿 |
| 生命周期 | 退出与重新打开是否正常，设置是否保留 |
| 双宠（可选） | 两只可同时运行，伙伴互动与快捷键不冲突 |

只测试启用的功能。涉及剪贴板时使用无敏感内容的测试文字。

发现问题时发：

```text
Windows 真机发现问题：
- 角色 key：[...]
- 触发步骤：[...]
- 预期行为：[...]
- 实际行为：[...]
- 截图或录屏：[附件]
- 报错：[原文，没有就写无]

请先定位原因，做最小必要修复，重新构建并检查相关动作。
涉及逻辑行为时运行相关测试；涉及共享代码时运行完整测试。
保持已确认的角色外形不变。告诉我如何复测。
```

## 6. 打包并交付

真机检查完成后发：

```text
真机验收完成，请为 <key> 制作交付包。

1. 确认图集是本次最新源文件生成的，完成必要的构建与测试。
2. 在 docs/<key>/使用说明.txt 写简短说明：
   系统要求、打开和退出、主要操作、设置入口、实际快捷键、
   可选功能的数据处理方式和已知限制。以实际实现为准。
3. 运行 .\build.ps1 dist -Char <key>。
4. 检查 ZIP 内的 exe、使用说明和字体授权文件。
   不包含 reference_pics、原始照片、调试日志或无关个人资料。
5. 告诉我 ZIP 的准确路径、版本、大小、检查结果和未验证事项。

不要自动上传、发布 Release、推送代码或把文件发送给别人。
如果需要分享这些内容，我会另行提出。
```

`build.ps1 dist` 会把 `docs/<key>/使用说明.txt`（如果存在）放进交付包。输出在 `dist/`，文件名取决于角色 `id` 和程序版本，不能假定与 key 相同。

发出第一版后保持角色 `id` 稳定：它关联数据目录、单实例和自启标识。改显示名称通常不需要改 id。

## 7. 后续定制 Prompt

### 两只宠物做伙伴

```text
让 <keyA> 与 <keyB> 成为当前同一台电脑上的伙伴。
先检查两只的 id、partner、duty 和 hotkey。
保持各自 id 稳定，将 partner 指向对方 id，设置不同 duty 和快捷键；
按当前实现解释哪个角色负责举牌、提醒和专注监督。
构建并检查两只，再给我同机双宠验收步骤。
不要把它扩展或描述成跨电脑联机。
```

### 新衣服或食物

```text
给 <key> 增加 [具体衣服或食物]。
先检查能否复用现有换色表、部件和动作；需要新增时沿用项目格式。
保持既有外形和动作不变，生成预览并检查所有受影响的造型。
食物需核对 character.txt 中的动作引用和台词触发帧。
做完构建、检查并告诉我如何在运行时使用它。
```

### 中断后继续

```text
继续制作 <key>。先读取当前文件和已有修改，
总结已完成、待完成、最近已确认的外形与已知问题。
不要重新 new，不要重置或覆盖工作。
如果当前会话缺少外形确认记录，向我索取定稿截图，
不要把自己的猜测当成已确认结果。
从最早未完成的阶段继续，并如实区分已执行与待执行的验证。
```

## 8. 常见问题

| 情况 | 处理 |
|---|---|
| 不知道选哪个模型 | 用当前可用的代码与图片理解模型，先做小范围预览再决定是否提高推理强度 |
| PowerShell 阻止脚本 | 先检查文件来源与当前策略；受组织管理时遵守组织设置。不要默认永久放宽系统策略 |
| 找不到 csc.exe | 检查 Windows .NET Framework 编译器；Linux/macOS 云端不能照搬这条 Windows 构建链 |
| 构建成功但没有窗口 | 在自己 Windows 交互桌面的 PowerShell 运行；Agent 可能运行在隔离桌面 |
| 报 SmartScreen 或杀毒告警 | 检查来源、签名和具体检测结果；不能仅凭“未签名”就断言安全，也不要盲目加白名单 |
| 看起来不像 | 给出具体可见特征和对应截图，先修形象再补动作 |
| 编译通过但动作穿帮 | 逐帧检查；编译与单元测试不能代替视觉验收 |
| Codex 说完成但没有预览 | 要求提供实际生成的文件和检查结果；无法查看时应明确列为待验收 |
| 额度不足或需要换会话 | 保留当前修改，用续做提示词恢复；个人照片和设定不要写入公开进度文件 |

## 9. 一次复制的总提示词

先在项目目录打开 Codex，替换下面的设定，再发送。这个总提示词已经包含分阶段暂停要求，无需同时发送前面所有分步提示词。

```text
你要基于当前 desktop-pet 仓库，帮我制作一只可运行、可交付的 Windows 像素桌宠。
请用中文沟通，沿用现有引擎和文本像素图管线，完成实际文件修改与可执行的验证。

【我的设定】
key：
显示名：
参考图片或本地图片路径：
角色身份：
最重要的 3～5 个外观特征：
身材比例：
默认服装：
额外服装：
发型变化：
性格与口头禅：
食物：
保留或关闭的功能：
双宠需求：
不能改变的细节：

【阶段与停点】
1. 先只读项目：适用的 AGENTS.md、README.md、docs/MAKE_YOUR_PET.md、
   art/README.md、docs/ANIMATION_GUIDE.md、build.ps1。
   检查实际角色、当前修改、系统和编译器；说明是否能 Windows 构建和真机运行。
   查看参考图并总结特征，看不到就说明。
   提交分阶段计划，等待我确认，暂时不要修改。
2. 计划批准并进入执行模式后，为不存在的 key 使用 build.ps1 new 新建角色；
   已有则继续，不覆盖。完成默认形象，构建并查看预览，
   在形象确认处暂停，不先批量做完所有服装。
3. 我确认形象后，完成约定的动作、造型、食物与台词；
   在此已批准范围内自主修复，不逐文件请求确认。
4. 修改 art/<key>/ 与 assets/<key>/ 源配置，生成 atlas/icon；
   保持 id 唯一稳定、台词场景完整、锚点与镜像机制正确。
   不用独立 PNG 冒充可用图集，不重写不必要的引擎逻辑。
5. 环境允许时执行：
   .\build.ps1 art -Char <key>
   .\build.ps1 -Char <key>
   .\build.ps1 test
   检查总览、逐帧、衣柜与可用动图。修复问题后重新检查。
   不能执行的事项明确列为待验证，不声称已经通过。
6. 给我 Windows 运行命令与简短真机清单；等待我反馈。
   我发现问题时，依据截图和步骤修复，保留确认过的外形。
7. 真机通过后写 docs/<key>/使用说明.txt，运行 dist，
   检查压缩包内容，提供路径和验证摘要。
   不自动上传、推送、发布或发送文件。

【工作边界】
- 保留已有修改；不覆盖其它角色，不重置仓库。
- 图片只用于当前制作，不提交参考照片；不声称云端图片理解是纯本地处理。
- 遇到缺失素材、权限或环境，说明具体阻塞并完成可执行部分。
- 不通过删测试、关闭安全防护或编造结果来宣称完成。
```
